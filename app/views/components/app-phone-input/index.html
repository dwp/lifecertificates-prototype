Pattern

Ask users for a phone number

Help users enter a phone number, with or without a country code.

When to use this pattern

Use this pattern when users need to enter a phone number.

You can use it to ask for:

  • a phone number only
  • a phone number with a separate country code

Ask for the country code separately if your service needs to store, validate or use it separately from the rest of the phone number.

When not to use this pattern

Do not ask for a country code if your service does not need one.

For example, if your service only accepts UK phone numbers, or already knows the user’s country, a single phone number input may be simpler.

Do not split the phone number into separate fields unless there is a clear user or service need.

How it works

The pattern uses a fieldset and legend to group the related inputs together as one question.

If you need a country code, show it before the phone number input.

What is your phone number?

Country code: +44
Phone number: 7700900123

If you do not need a country code, only show the phone number input.

What is your phone number?

Phone number: 07700 900123

Country code

Make the country code optional in the component configuration.

Show the country code input when your service needs an international number or needs to validate the country code separately.

Hide the country code input when users only need to provide a national phone number.

With country code 

{{ appPhoneInput({
  id: "phone-number",
  namePrefix: "phone-number",
  fieldset: {
    legend: {
      text: "What is your phone number?",
      isPageHeading: true,
      classes: "govuk-fieldset__legend--l"
    }
  },
  hint: {
    text: "Include the country code and phone number. For example, +44 7700900123."
  },
  countryCode: {
    value: data["phone-number-country-code"]
  },
  nationalNumber: {
    value: data["phone-number-national-number"]
  }
}) }}

Without country code 

{{ appPhoneInput({
  id: "phone-number",
  namePrefix: "phone-number",
  fieldset: {
    legend: {
      text: "What is your phone number?",
      isPageHeading: true,
      classes: "govuk-fieldset__legend--l"
    }
  },
  hint: {
    text: "For example, 07700 900123."
  },
  countryCode: {
    show: false
  },
  nationalNumber: {
    value: data["phone-number-national-number"]
  }
}) }}

Use a fieldset and legend

Use a fieldset to group the inputs because they form one answer.

The legend should usually be the question, for example “What is your phone number?”.

If the page asks one question, the legend can be the page heading.

Labels

Use short, clear labels for each input.

If you include the country code input, use:

  • Country code
  • Phone number

If you do not include the country code input, use:

  • Phone number

Avoid abbreviations such as “CC”, “intl code” or “dialling code” unless your research shows users understand them.

Hint text

Use hint text to show the expected format.

If asking for a country code

Include the country code and phone number. For example, +44 7700900123.

If not asking for a country code

For example, 07700 900123.

The plus sign

If you ask for a country code, show the plus sign as a GOV.UK input prefix.

Do not ask users to type the plus sign if your service only stores the numeric country code.

Some users may still type the plus sign into the country code field. Allow for this in validation by removing the plus sign before validating or storing the value.

Validation

Validate the fields that are shown to the user.

If country code and phone number are shown

Validate the country code and phone number separately.

If nothing is entered

Enter your phone number

If the country code is missing

Enter a country code

If the country code is not valid

Country code must be 2 numbers

If the phone number is missing

Enter a phone number

If the phone number is too long

Phone number must be 20 numbers or fewer

If only phone number is shown

Only validate the phone number field.

If nothing is entered

Enter a phone number

If the phone number is too long

Phone number must be 20 numbers or fewer

Accessibility

This pattern uses:

  • a fieldset to group related inputs
  • a legend to describe the group
  • visible labels for each input
  • hint text connected to the fieldset using aria-describedby
  • text inputs so leading zeroes are not removed
  • a GOV.UK input prefix for the plus sign when the country code is shown

Research considerations

Test whether users:

  • understand what “country code” means
  • notice that the plus sign is already provided
  • know whether to include leading zeroes in the phone number
  • expect to enter the full phone number in one field
  • can complete the pattern on mobile devices
  • find it easier with or without a separate country code field
