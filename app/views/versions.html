Versions record material changes to the prototype and show how the service design has developed.

Version numbers

Minor versions

Minor versions are used while a design is being developed.

For example:

0.1 → 0.2 → 0.3

They may include changes to journeys, content, interactions and service behaviour.

Major versions

A major version is created when a design becomes the approved baseline.

For example:

Draft 0.3 → Current 1.0

Further development continues through minor versions until the next design baseline is approved.

Draft 1.1 → Draft 1.2 → Current 2.0

Version status

Version status shows where a version sits in the design lifecycle.

{{ govukTag({ text: "Draft", classes: "govuk-tag--blue" }) }}
A design that is still being developed and has not been approved as the current baseline.
{{ govukTag({ text: "Current", classes: "govuk-tag--green" }) }}
The approved prototype version and current design baseline.
{{ govukTag({ text: "Previous", classes: "govuk-tag--grey" }) }}
A previous design baseline replaced by a newer approved version.
{{ govukTag({ text: "Archived", classes: "govuk-tag--grey" }) }}
A historic or discontinued version retained for context.

Design track

Design track describes the type of work represented by the version.

Core
Work intended to contribute to the agreed service design.
Exploratory
Concept work that tests a different direction or assumption.

Exploratory work can move into the core design or be archived if it is not taken forward.

Research status

Research status shows whether a version has been tested with customers.

Not tested
No customer research has been completed for this version.
Planned
Customer research is planned.
In testing
Customer research is in progress.
Tested
Customer research has been completed.

How the fields work together

Version status, design track and research status describe different aspects of a version.

Version status
Where the version sits in the design lifecycle.
Design track
Whether the work supports the core design or explores another direction.
Research status
How far the version has progressed through customer research.

Version lifecycle

A design normally moves through these lifecycle states:

Draft → Current → Previous → Archived

Draft work can move directly to Archived if it is not taken forward.

Research runs alongside the version lifecycle:

Not tested → Planned → In testing → Tested
